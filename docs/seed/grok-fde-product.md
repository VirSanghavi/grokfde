# Grok FDE

**Every prospect gets an engineer.**

## What we sell

Grok FDE turns a company's documentation, APIs, pricing, security materials, case studies, and optional MCP tools into a persistent AI Forward-Deployed Engineer.

Prospects interact with the same engineer across:

- Chat
- Email
- Realtime voice calls

## Who buys

- Technical B2B companies with complex products
- AI / ML infrastructure teams
- Developer platform teams
- Founders who lose deals because engineers cannot join every call

## Value proposition

Train the FDE on your company once. Every prospect can talk to a technical engineer instantly — without scheduling a human SE.

## Core capabilities

1. **Company knowledge ingestion** via paste, file upload, URL, and MCP
2. **Structured company understanding** (products, integrations, objections, security facts)
3. **Persistent prospect memory** across chat, email, and calls
4. **Technical discovery** — understands stack, requirements, constraints
5. **MCP action layer** — create sandboxes, estimate cost, inspect accounts
6. **Architecture generation** — prospect-specific integration diagrams
7. **Grok Imagine collateral** — technical and executive visuals
8. **Human escalation** — never fabricates legal, pricing exceptions, or compliance claims
9. **Realtime voice** with the same identity and memory as chat

## How it works

1. Company creates an FDE (name, voice)
2. Uploads product knowledge into xAI Files / Collections
3. Optionally connects remote MCP servers for real tools
4. Shares a hosted page such as `/fde/{slug}`
5. Prospects chat, call, and email the same FDE
6. Company dashboard shows conversations and "Needs You" escalations

## Technical integrations

Works alongside existing customer infrastructure:

- Kubernetes
- AWS / GCP / Azure
- Salesforce and CRMs
- GitHub / CI systems
- Internal deployment platforms (especially if they expose MCP or API docs)

Grok FDE does **not** require ripping out orchestration. It sits next to the stack as a technical selling and implementation layer.

## MCP tools (example vendor surface)

- `create_sandbox` — trial environment for a prospect
- `estimate_cost` — indicative pricing estimate
- `list_capabilities` — capability list tailored to stack
- `generate_config` — starter integration config
- Customer MCP tools (deploy, inspect, provision) when connected

## Security and trust rules

- Answers must be grounded in company documentation
- Do not fabricate features, integrations, pricing, or security claims
- Do not invent HIPAA/BAA, SOC2, GDPR contractual commitments
- If docs are insufficient, admit uncertainty and escalate to a human

## Implementation path for a prospect

1. Share current deployment stack
2. FDE maps current vs proposed architecture
3. Optional sandbox via MCP
4. Implementation checklist and technical proposal
5. Human SE joins only for exceptions and close

## Pricing

Enterprise pricing is custom. Demo sandboxes can be created during evaluation. Do not invent dollar amounts unless present in company knowledge.
